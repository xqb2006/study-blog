# 从零部署个人博客：GitHub + Cloudflare Pages + 网页后台

> 本教程适用于本项目当前版本。
>
> 目标：不用购买服务器、不使用数据库，通过 GitHub 保存博客内容，使用 Cloudflare Pages 自动构建发布，并通过网页后台写文章。

## 一、你最终会得到什么

完成部署后，你会拥有：

- 一个免费的 `*.pages.dev` 博客地址；
- 一个 `/admin/` 网页管理后台；
- 使用 GitHub OAuth 登录后台；
- 在网页中新建、编辑、发布和删除文章；
- 在网页中上传图片并插入文章；
- 修改头像、个人资料、社交链接、导航、公告、BGM、分类和系列；
- GitHub 自动保存文章、图片和站点配置；
- 每次 GitHub 内容更新后，Cloudflare Pages 自动重新构建博客。

项目工作流程如下：

```text
你在网页后台保存内容
        ↓
Cloudflare Pages Functions 校验登录并调用 GitHub API
        ↓
文章、图片或配置提交到你的 GitHub 仓库
        ↓
GitHub 通知 Cloudflare Pages
        ↓
Cloudflare 执行 npm run build
        ↓
博客前台自动更新
```

## 三、准备工作

你只需要准备：

1. 一个 GitHub 账号；
2. 一个 Cloudflare 账号；
3. 一个可以正常访问 GitHub 和 Cloudflare 的浏览器环境。

不需要准备：

- 服务器；
- 数据库；
- Node.js 环境；
- 付费 CMS；
- 必须购买的域名。

首次部署建议使用电脑操作，整个过程通常需要 20—40 分钟。

## 四、复制项目到自己的 GitHub

### 4.1 使用 Fork（推荐）

1. 打开本项目的 GitHub 页面；
2. 点击右上角 **Fork**；
3. 在 Owner 中选择你自己的 GitHub 账号；
4. 设置仓库名称，例如 `study-blog`；
5. 点击 **Create fork**。

完成后，你应该拥有类似下面的仓库：

```text
https://github.com/你的用户名/study-blog
```

后续文章、图片和配置都会保存到这个仓库。不要把仓库 Fork 到别人的账号下。

### 4.2 仓库可见性建议

本项目默认适合使用公开仓库，因为 Cloudflare Pages 需要读取博客源码，博客文章本身也会发布到公网。

但是以下内容绝对不能提交到仓库：

- GitHub OAuth Client Secret；
- `SESSION_SECRET`；
- GitHub Personal Access Token；
- 任何 API Key；
- 邮箱密码或邮箱授权码。

这些内容只能填写在 Cloudflare 的 **Variables and Secrets** 中，并且要选择 Secret 类型。

## 五、先修改博客基本资料

在你的 GitHub 仓库中打开：

```text
config/site.yaml
```

点击右上角的编辑按钮，优先修改 `site` 部分。示例：

```yaml
site:
  title: 小明的博客
  subtitle: 记录、思考与分享
  name: 小明
  author: 小明
  description: 这是小明的个人博客
  avatar: /img/avatar.webp
  url: https://你的项目名.pages.dev
```

注意：

- `url` 第一次可以暂时填写 `https://你的项目名.pages.dev`；
- Cloudflare 部署完成后，再把它改成最终地址；
- 图片路径应使用 `/img/...`，不要填写电脑上的 `C:\` 或 `F:\` 路径；
- 保存文件时点击 **Commit changes**。

## 六、部署到 Cloudflare Pages

### 6.1 创建 Pages 项目

1. 登录 Cloudflare 控制台；
2. 进入 **Workers & Pages**；
3. 点击 **Create application**；
4. 选择 **Pages**；
5. 选择 **Connect to Git**；
6. 连接你的 GitHub 账号；
7. 选择刚才 Fork 的博客仓库。

如果看到项目名称已存在，换一个 Cloudflare Pages 项目名称即可。项目名称不必和 GitHub 仓库名称完全一致。

### 6.2 填写构建设置

请按下面填写：

| 配置项 | 填写内容 |
| --- | --- |
| Project name | 例如 `study-blog` |
| Production branch | `main` |
| Framework preset | `Astro`，如果没有就选 `None` |
| Build command | `npm run build` |
| Build output directory | `dist` |
| Root directory | 留空 |
| Node.js version | 推荐 `22`；没有该选项时使用 Cloudflare 默认版本 |

然后点击 **Save and Deploy**。

### 6.3 确认首次部署

部署成功后，Cloudflare 会提供一个地址：

```text
https://你的项目名.pages.dev
```

打开这个地址，确认能看到博客首页。

如果首页正常，继续打开：

```text
https://你的项目名.pages.dev/admin/
```

此时后台可能还不能登录，这是正常的，因为 GitHub OAuth 和 Cloudflare 变量还没有配置完成。

## 七、创建 GitHub OAuth App

网页后台使用 GitHub OAuth 登录，不使用单独的后台密码。

### 7.1 打开 OAuth App 页面

在 GitHub 中进入：

```text
头像 → Settings → Developer settings → OAuth Apps → New OAuth App
```

### 7.2 填写 OAuth App

假设你的博客地址是：

```text
https://study-blog.pages.dev
```

填写：

| 字段 | 填写内容 |
| --- | --- |
| Application name | `study-blog-admin` |
| Homepage URL | `https://study-blog.pages.dev` |
| Application description | 可填写“我的博客后台” |
| Authorization callback URL | `https://study-blog.pages.dev/api/admin/callback` |

如果你以后绑定了自定义域名，OAuth 回调地址也必须改成自定义域名版本，例如：

```text
https://blog.example.com/api/admin/callback
```

创建后保存两个值：

- **Client ID**：可以放入普通变量；
- **Client secret**：只能放入 Cloudflare Secret，不要发给别人。

## 八、配置 Cloudflare 环境变量

进入 Cloudflare：

```text
Workers & Pages → 你的项目 → Settings → Variables and Secrets
```

在 **Production** 环境添加以下变量：

| 变量名 | 类型 | 填写内容 |
| --- | --- | --- |
| `GITHUB_CLIENT_ID` | Text | GitHub OAuth App 的 Client ID |
| `GITHUB_CLIENT_SECRET` | Secret | GitHub OAuth App 的 Client secret |
| `SESSION_SECRET` | Secret | 至少 32 位随机字符串 |
| `GITHUB_REPOSITORY_OWNER` | Text | 你的 GitHub 用户名 |
| `GITHUB_REPOSITORY_NAME` | Text | 你的博客仓库名，例如 `study-blog` |
| `GITHUB_REPOSITORY_BRANCH` | Text | `main` |
| `GITHUB_ADMIN_USERNAME` | Text | 允许进入后台的 GitHub 用户名 |

示例：

```text
GITHUB_CLIENT_ID=Iv1.xxxxxxxxxxxxxxxx
GITHUB_CLIENT_SECRET=只填写在 Secret 中
SESSION_SECRET=一串长度至少 32 位的随机字符
GITHUB_REPOSITORY_OWNER=xqb2006
GITHUB_REPOSITORY_NAME=study-blog
GITHUB_REPOSITORY_BRANCH=main
GITHUB_ADMIN_USERNAME=xqb2006
```

其中：

- `GITHUB_REPOSITORY_OWNER` 是 GitHub 用户名，不是显示名称；
- `GITHUB_REPOSITORY_NAME` 是仓库名，不要填写完整网址；
- `GITHUB_ADMIN_USERNAME` 必须与 GitHub 登录用户名完全一致；
- `SESSION_SECRET` 不要使用简单密码，建议使用随机字符串；
- `GITHUB_CLIENT_SECRET` 和 `SESSION_SECRET` 必须设置为 Secret；
- 不要把这些值写入 `README.md`、前端代码或 GitHub 仓库。

本项目默认使用登录用户的 OAuth Token 操作 GitHub。通常不需要额外设置 `GITHUB_TOKEN`；不要为了省事把个人 Token 暴露到前端。

## 九、重新部署并登录后台

保存变量后，进入：

```text
Deployments → Redeploy
```

也可以在 GitHub 提交一次无害的 README 修改，触发自动部署。

部署完成后打开：

```text
https://你的项目名.pages.dev/admin/
```

点击 GitHub 登录。如果配置正确，登录成功后会进入后台首页。

### 常见登录失败原因

- OAuth 回调地址少了 `/api/admin/callback`；
- 回调地址使用了错误的域名；
- `GITHUB_ADMIN_USERNAME` 填的是昵称，不是 GitHub 登录名；
- `GITHUB_CLIENT_SECRET` 填错或放成了普通 Text；
- Cloudflare 变量只配置在 Preview，没有配置 Production；
- 修改变量后没有重新部署；
- 浏览器缓存了旧的登录状态。

## 十、第一次进入后台后的配置顺序

建议按下面顺序设置：

### 10.1 站点资料

进入后台的站点设置，填写：

- 博客标题；
- 博主名称；
- 个人简介；
- 头像路径；
- 社交链接；
- 网站地址。

保存后，后台会提交配置到 GitHub，Cloudflare 会自动重新部署。

### 10.2 上传头像和图片

进入素材库上传图片。图片会保存到：

```text
public/img/
```

文章中使用的路径通常是：

```text
/img/文件名.webp
```

不要填写：

```text
C:\Users\你的名字\Desktop\图片.webp
F:\图片.webp
```

### 10.3 分类花园

进入分类管理，先保存分类 URL 映射，例如：

| 分类名称 | URL slug |
| --- | --- |
| 笔记 | note |
| 前端 | front-end |
| 随笔 | essay |

保存后，新建文章和导入 Markdown 时可以选择这些分类。

当前分类逻辑支持：

- 预先建立分类；
- 单独删除分类 URL 映射；
- 彻底删除分类；
- 删除分类时清理文章引用和首页入口。

删除分类前请认真阅读确认弹窗，因为彻底删除可能会修改多篇文章。

## 十一、如何发布第一篇文章

### 11.1 新建文章

1. 进入后台；
2. 点击 **新建文章**；
3. 填写标题；
4. 选择分类；
5. 填写标签；
6. 点击创建；
7. 在文章编辑器中填写正文；
8. 点击保存或发布。

文章会写入：

```text
src/content/blog/
```

### 11.2 导入 Markdown

如果你已经有 Markdown 文件：

1. 点击 **导入 Markdown**；
2. 选择本地 `.md` 或 `.mdx` 文件；
3. 选择默认分类；
4. 填写标签；
5. 确认导入；
6. 进入编辑器检查格式并保存。

### 11.3 保存后多久能看到

正常流程是：

```text
后台保存
→ GitHub 出现新提交
→ Cloudflare 开始部署
→ 部署完成后前台更新
```

通常需要几十秒到几分钟。首次构建或内容较多时可能更久。

## 十二、日常写作建议

- 文章重要修改前，先确认 GitHub 仓库中有最近的提交记录；
- 不要同时在 CMS 和 GitHub 网页编辑同一篇文章；
- 如果刚在 GitHub 网页改过文章，先等待 Cloudflare 部署结束，再在后台编辑；
- 图片文件名尽量使用英文、数字、短横线；
- 图片路径使用 `/img/...`，不要使用本地电脑路径；
- 分类名称和分类 URL slug 建议保持稳定，不要频繁修改；
- 删除文章、图片、分类前先阅读确认弹窗；
- 定期查看 GitHub 提交记录，GitHub 本身就是你的内容历史备份。

## 十三、GitHub 网页直接写文章

如果后台暂时打不开，可以直接在 GitHub 网页编辑 Markdown：

1. 打开仓库；
2. 进入 `src/content/blog/`；
3. 新建或编辑 `.md` 文件；
4. 添加 YAML Frontmatter；
5. 点击 **Commit changes**。

最小文章示例：

```markdown
---
title: 我的第一篇文章
date: 2026-08-23 12:00:00
description: 文章摘要
categories:
  - 笔记
tags:
  - 博客
draft: false
sticky: false
cover: /img/cover/10.webp
catalog: true
---

这里写正文。
```

保存后，Cloudflare Pages 会自动构建。

## 十四、自定义域名（可选）

如果你有自己的域名：

1. 进入 Cloudflare Pages 项目；
2. 打开 **Custom domains**；
3. 点击 **Set up a custom domain**；
4. 按提示绑定域名；
5. 把 `config/site.yaml` 中的 `site.url` 改成新域名；
6. 修改 GitHub OAuth App 的 Homepage URL；
7. 修改 GitHub OAuth App 的 Authorization callback URL；
8. 重新部署并测试登录。

回调地址必须与实际访问后台的域名一致：

```text
https://你的域名/api/admin/callback
```

## 十五、故障排查

### 15.1 页面显示 Cloudflare Error 1101

这通常表示 Cloudflare Pages Function 运行时抛出了异常。排查步骤：

1. 进入 Cloudflare Pages 项目；
2. 打开 **Deployments**；
3. 点击最新部署；
4. 查看构建日志；
5. 如果构建成功，再查看 Functions 或运行时日志；
6. 确认所有 Production 变量都已填写；
7. 确认 `SESSION_SECRET`、OAuth Secret 没有留空；
8. 重新部署。

### 15.2 GitHub 登录失败

重点检查：

- OAuth App 的回调地址；
- Cloudflare 的 `GITHUB_CLIENT_ID`；
- Cloudflare 的 `GITHUB_CLIENT_SECRET`；
- `GITHUB_ADMIN_USERNAME`；
- 当前访问的域名是否与 OAuth App 配置一致。

### 15.3 后台读取失败或连接超时

检查：

- 是否已登录正确的 GitHub 账号；
- GitHub OAuth 是否授权成功；
- Cloudflare 变量是否部署到 Production；
- GitHub 当前是否可以访问；
- Cloudflare Functions 是否出现运行时错误。

### 15.4 图片上传成功但不显示

检查图片路径：

- 正确：`/img/avatar.webp`；
- 错误：`public/img/avatar.webp` 作为前台 URL；
- 错误：`C:\Users\...` 或 `F:\...` 本地路径。

然后检查：

1. GitHub 仓库中是否真的出现了图片；
2. 图片是否位于 `public/img/`；
3. Cloudflare 是否完成最新部署；
4. 浏览器是否缓存了旧页面。

### 15.5 后台修改后首页没有更新

先确认：

1. GitHub 是否产生了新的提交；
2. Cloudflare 是否开始了新的部署；
3. 部署是否成功；
4. 是否刷新了浏览器缓存。

如果 GitHub 没有新提交，说明后台接口或登录会话有问题；如果有提交但部署失败，查看 Cloudflare 部署日志。

### 15.6 新建文章看不到分类

先进入分类管理，保存分类 URL 映射，再重新打开新建文章窗口。

当前版本会合并以下分类：

```text
已有文章使用过的分类 + 分类花园中已配置的分类
```

### 15.7 构建提示文章 ID 重复

如果构建日志提示类似：

```text
Duplicate id found
```

说明 `src/content/blog/` 中存在两个文件生成了相同的文章 ID。检查是否有重复文件名、重复 slug 或重复文章副本。不要随意删除文件，先在 GitHub 提交记录中确认来源。

## 十六、安全建议

- GitHub 账号开启 2FA；
- Cloudflare 账号开启 2FA；
- 不要把 OAuth Secret、Session Secret 或 Token 发给任何人；
- 不要在公共电脑登录后台；
- 使用完后台后点击退出；
- 定期查看 GitHub 仓库提交记录；
- 不要给陌生人仓库写权限；
- 建议保护 GitHub 的 `main` 分支，禁止强制推送；
- 如果怀疑账号泄露，立即撤销 GitHub OAuth App 授权、修改账号密码并重新生成密钥；
- Cloudflare 变量修改后必须重新部署。

## 十七、更新项目

如果你是从自己的仓库部署，日常更新有两种方式：

### 方式一：直接同步上游更新

适合熟悉 Git 的用户。更新前先备份自己的 `config/site.yaml`、`src/content/blog/` 和 `public/img/`。

### 方式二：使用本项目发布的新版本

如果项目维护者发布了更新，先查看更新说明，再合并到自己的仓库。不要直接覆盖自己的文章、图片和配置。

更新后由 Cloudflare Pages 自动重新部署。
